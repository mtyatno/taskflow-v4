# Live Edit (panel detail task) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tombol on/off "Live Edit" di daftar task yang menampilkan detail task terpilih di panel kanan (bisa diedit dan tersimpan otomatis), memakai satu komponen isi detail yang sama dengan modal.

**Architecture:** PR A memisahkan isi `TaskDetailModal` menjadi `TaskDetailBody` tanpa mengubah perilaku. PR B menambah modul murni `static/offline/liveedit.js` (ketersediaan, pilihan task, pembanding field, pengendali autosave `createAutosaver`), varian `panel` di `TaskDetailBody`, penanda terpilih di baris/kartu, lalu tombol Live Edit + tata letak dua kolom + `TaskDetailPanel` di `TaskListView`.

**Tech Stack:** React 18 tanpa JSX (`static/index.html` sudah terkompilasi: tulis `React.createElement`), CSS `static/app.css`, modul UMD `static/offline/*.js`, `node --test`, pytest, Playwright (E2E manual).

**Spec:** `docs/superpowers/specs/2026-10-26-live-edit-design.md` (salinan Project `claude/spec-live-edit-2026-10-26.md`).

## Keputusan rencana (menyempurnakan spec; spec ikut diperbarui)

- **R1 — pemicu simpan project/context/progress.** `ComboSelect` (`static/ui-components.js`) memanggil `onChange` di setiap ketikan pada mode nama baru, dan `onChange("")` saat "+ Baru" dipilih. Maka `saveTrigger("project"|"context", v)` = `"idle"` bila `v` tidak kosong, `"blur"` bila kosong (nilai kosong hanya tersimpan saat keluar field atau flush). *(Bagian project/context diganti R19: selalu `"blur"`.)* `saveTrigger("progress")` = `"blur"`; range memanggil `commit("progress")` pada `pointerup`, `keyup`, dan `blur`. Field lain sesuai spec §5.5.
- **R2 — autosave sebagai pengendali murni.** Orkestrasi (timer idle, satu simpan berjalan, flush, retry, gabung perubahan luar) ada di `TF.liveedit.createAutosaver` sehingga bisa diuji di Node dengan timer palsu. Hook React `useTaskAutosave` hanya pembungkus.
- **R3 — pilihan task lewat reducer murni** `TF.liveedit.selectionReducer` dengan keadaan `{ref, snapshot, cleared}` (spec §6.2: `cleared` = "Pilih task di daftar" setelah Hapus).
- **R4 — `TaskDetailBody` mengembalikan `React.Fragment`.** Overlay "Task dengan tag" (`position: absolute; inset: 0`) tetap berjangkar ke `modal-content` (modal) atau `aside.tl-live-panel` (panel, `position: sticky`), sehingga render modal identik.
- **R5 — sorotan kartu Kanban inline.** Gaya `KanbanCard` inline dan handler hover menulis border/shadow, jadi kartu terpilih memakai `background: "linear-gradient(var(--bg-selected), var(--bg-selected)), var(--bg-card)"` inline. `TaskRow` dan `CompactRow` memakai kelas `is-selected`.
- **R6 — keadaan "tidak tersedia" tanpa body.** Spec §5.3 dan §6.4 berbeda; yang dipakai §5.3: panel hanya menampilkan teks "Task ini sudah dihapus atau tidak bisa diakses lagi." Respons `GET /api/tasks/:id` yang `null` dianggap tidak ditemukan.
- **R7 — tinggi deskripsi.** Textarea deskripsi di panel `rows: 4` dan bisa di-resize vertikal (seperti modal); pertumbuhan otomatis sampai 12 baris dari spec §7.1 dibatalkan karena `MentionInput` tidak meneruskan ref.
- **R8 — tes Node ikut CI** lewat jembatan `tests/test_liveedit_node.py` (workflow `test.yml` hanya menjalankan pytest), pola `tests/test_app_update_node.py`.

## Rulings saat eksekusi (R9–R16, R19, R21)

Keputusan yang diambil selama pelaksanaan (ledger lengkap: `.superpowers/sdd/2026-10-26-live-edit/progress.md`); task di bawah tidak ditulis ulang. Perilaku akhir sudah dilebur ke spec.

- **R9 — panel mempertahankan tag.** `PUT` yang memuat `title` menimpa tag dengan `#tag` dari judul, jadi `TF.liveedit.titleWithTags(title, tags)` (Task 3) dipakai `useTaskAutosave` (Task 5) pada setiap simpan judul dari panel; tag dimuat ulang sesudah simpan yang mengirim judul. Modal tidak diubah.
- **R10 — form dinormalkan sesudah simpan.** `createAutosaver` menyetel `form[f] = saved[f]` untuk field terkirim yang form-nya belum berubah sejak dikirim (judul di-trim, dll.), supaya `mergeExternal` tidak melihat field "dirty" basi.
- **R11 — simpan eksplisit vs bukan.** `commit`/`flush`/`retry` eksplisit; perubahan "now" dan timer idle bukan, dan membuang field pemicu `blur` (judul, progress, project/context kosong); eksplisit yang tertunda dibawa ke simpan berikutnya.
- **R12 — flush + dispose.** `dispose()` tetap mengirim flush yang sudah antre (fire-and-forget, tanpa state/emit); flush eksplisit yang antre dicoba juga sesudah `put` yang gagal.
- **R13 — `validateTitle` menolak judul hanya-tag.** Judul yang kosong setelah `#tag` dibuang (regex server) mengembalikan "Judul tidak boleh kosong"; kalau tidak, setiap autosave berikutnya gagal.
- **R14 — judul menunggu daftar tag.** `put` menunggu daftar tag termuat (gagal → ambil ulang sekali) sebelum mengirim judul, supaya `titleWithTags(title, [])` tidak menghapus tag.
- **R15 — tinggi panel diukur langsung.** `max-height = max(200, innerHeight − max(top, rect.top) − 16)` lewat pendengar `scroll`/`resize` pasif + rAF dan pengukuran ulang tiap render, agar bar aksi terlihat sebelum halaman digulir.
- **R16 — keadaan "sudah dihapus" dibuang saat task ditemukan lagi** (pemeriksaan satu kali dipasang ulang; dipertahankan selama panel tersembunyi); tes CSS dibatasi ke blok Live Edit (penanda akhir di `app.css`).
- **R19 — project/context tidak tersimpan setengah diketik (tinjauan akhir #1, mengganti bagian project/context R1).** Server membuat project / tahap Kanban untuk setiap nama yang belum ada, jadi `"idle"` untuk nama tidak kosong membuat "Mark" tersimpan (dan dibuat) sebelum "Marketing". `saveTrigger("project"|"context")` selalu `"blur"`; di panel, memilih opsi yang sudah ada di scope (`scopeProjects`/`scopeContexts`, daftar yang sama dengan `options` `ComboSelect`) langsung `auto.commit(field)`; nama yang diketik tersimpan saat blur pembungkus field, `Enter` di pembungkus (`onKeyDown`, bukan saat komposisi IME), atau flush.
- **R21 — tag dimuat ulang sebelum setiap simpan judul (tinjauan akhir #3, memperluas R14).** Chip tag dimuat sekali per mount, jadi simpan judul dengan daftar basi bisa memulihkan tag yang dihapus di tempat lain atau menghapus tag baru. `tagsForTitle` selalu `loadTags(task.id)` (GET lokal) tepat sebelum judul disusun dan memakai hasil muatan itu; gagal → sekali lagi; gagal lagi → ditolak ("Gagal menyimpan"). Chip panel juga dimuat ulang saat `task.updated_at` berubah (satu efek `[task?.id, tagsVersion]`; modal tetap `task.id`).
- **Penyimpangan Task 7 (tanpa nomor):** init pilihan juga berjalan saat daftar pertama kali berisi (`hasVisible`, layout effect); lebar area konten diukur tanpa scrollbar halaman (`clientWidth + scrollbar`) agar panel tidak berkedip di dekat 760 px.
